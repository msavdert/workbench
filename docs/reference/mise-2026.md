# mise reference (researched 2026-08-18)

Condensed from https://mise.jdx.dev and github.com/jdx/mise; verified against
mise 2026.8.8 on the box where marked [verified]. Anything marked
[unverified] came from web research only and must be checked before use.

## Profiles: how mac and box share one config

- Global config is `~/.config/mise/config.toml`. With `MISE_ENV=<env>` mise
  additionally loads `~/.config/mise/config.<env>.toml` [verified: created a
  temporary `config.box.toml`, `MISE_ENV=box mise config ls` listed both].
  Precedence: `config.<env>.toml` over `config.toml`.
- Decision for this repo: `home/mise/config.toml` = shared base (settings +
  tools both profiles want), `home/mise/config.mac.toml` and
  `home/mise/config.box.toml` = profile deltas. `home/install.sh <profile>`
  links all three and exports `MISE_ENV=<profile>` from the shell init
  (non-interactive part on the box, so agents get the same tools).
- `auto_env` / `mise.{os}.toml` platform files: reported by research as the
  future default, but `mise settings get auto_env` says the setting does not
  exist in 2026.8.8 [verified]. Do not rely on it. `.miserc.toml`
  [unverified]. `include = [...]` [unverified, probably not a thing].
- `.mise/conf.d/*.toml` and `.config/mise/conf.d/*.toml` are merged for
  project-local config [unverified for the global dir]. Not needed here.

## Backends

- Prefer `aqua:` when the tool is in the aqua registry (checksums,
  attestations); `github:` is the general fallback for GitHub releases.
  `ubi:` is deprecated: replace `ubi:owner/repo` with `github:owner/repo`.
- Registry short names resolve to aqua first for everything we need
  [verified: `mise registry gh` -> `aqua:cli/cli`; research: herdr ->
  `aqua:herdrdev/herdr`, agy -> `aqua:google-antigravity/antigravity-cli`,
  aws-cli -> `aqua:aws/aws-cli`, claude-code -> aqua/http, uv, starship,
  eza, fzf, zoxide, ripgrep, fd, jq, yq, shfmt, shellcheck, usage all
  aqua]. Use short names in the toml; do not pin backends unless the
  registry default is wrong (agent-vm pins `aqua:astral-sh/uv` for a stale
  registry entry - re-check whether that pin is still needed in phase 2).
- npm packages: `npm.package_manager = "bun"` is a documented setting
  (default `auto`) [verified setting exists]. Keep `npm:@oh-my-pi/...`
  as is.
- Claude Code: registry has `claude-code`, but this repo keeps the native
  installer (D7); do not add it to the toml.

## Lockfile

- `mise.lock` stores per-os-arch resolved URLs and checksums; settings
  `lockfile = true` maintains it, `locked = true` enforces it [verified:
  `locked` and `locked_verify_provenance` settings exist]. Env-specific
  lockfiles `mise.<env>.lock` [unverified for the global config dir].
- Decision: not in phase 2. The box takes `latest` for fast-moving agent
  tools on purpose; a lockfile fights that. Revisit for the mac profile if
  reproducibility becomes a problem. Backlog item in PLAN.md.

## Settings that matter for this repo

- `yes = true` (non-interactive), `not_found_auto_install = false` (agents
  must not trigger installs by typo), `paranoid = false` (default),
  `experimental = false` (default) - all present in agent-vm's toml today
  and still valid.
- `idiomatic_version_file_enable_tools = [...]` if projects use `.nvmrc`
  etc.; off by default. Enable per tool only when a project needs it.
- `trusted_config_paths`: add `~/work` on the box so project `mise.toml`
  files do not prompt agents [unverified interaction with `yes = true`].

## activate vs shims

- Non-interactive / agent shells: shims on PATH
  (`~/.local/share/mise/shims`), no `mise activate`. This is what agent-vm
  does above the interactive guard; keep it.
- Interactive human shell: `eval "$(mise activate bash)"` in the interactive
  block so `[env]` and per-directory tools apply while typing.

## Tasks

- toml tasks: `[tasks.<name>]` with `run`, `description`, `depends`,
  `sources`, `outputs`, `env`, `dir`, `hide`. Arg / usage-spec syntax
  [unverified] - read `mise.jdx.dev/tasks/toml-tasks.html` before using.
- File tasks: executables in `mise-tasks/` (or `.mise/tasks/`) with
  `#MISE description="..."` headers. Decision: tasks longer than one line
  (herdr:integrations, ssh:sync, mac:sync) become file tasks so shellcheck
  and shfmt cover them and secrets go through `opwith`, not toml.
- `mise run` no-ops when `sources`/`outputs` are unchanged; `mise watch`
  reruns on change.

## Secrets

- mise has no first-class `op://` templating. Documented options are fnox,
  SOPS files via `env._.file`, and inline age encryption (experimental).
- Decision: keep secrets outside mise entirely (D10): `opwith`, credential
  helper, tasks that shell out through `op`. Do not put secrets in `[env]`.

## Maintenance

- `mise up` (respects version prefixes), `mise outdated`, `mise prune`,
  `mise doctor` [verified to exist; output details not checked].
- New since 2025 and irrelevant here: S3/Forgejo/Conda backends, http
  backend templating, `[shell_alias]` section, monorepo task refs.
